## 觀察

- **問答中最有價值的問題**：
  - 第 1 輪 Q5（階段之間要不要強制先後順序）：開發者沒接受建議，選了強制先後順序。之後的優先序限制、截止日推算、確認排程的連帶處理，都是從這題展開的，範圍明顯變大。如果沒問，實作會照「只有顯示順序」做。
  - 第 3～5 輪的刪除與失敗處理（只刪還沒開始的事件、失敗時整個取消、事件已不存在視為成功）：都是資料處理，沒有給建議答案，開發者每題都明確選了。審查也沒有在這一塊找到 Missing AC。
  - 第 5 輪 Q1（「當 ACID 處理」要做到什麼程度）：開發者在選項旁加了自己的備註，和選項的內容衝突，靠追問才釐清。
- **多餘或重複的問題**：附建議答案的題目被接受了 94%，像「只有兩層」「子任務不能搬家」這類，幾乎都是直接回答「是」。官方文件提醒過，這可能是開發者被動附和的訊號。但這次開發者有 2 題沒接受建議，12 題沒附建議的也都明確回答了，不算完全被動。
- **Missing AC 的來源**（2026-11-06 重新分類後）：8 項裡，3 項（R1#2、R1#4、R1#5）來自第 6 輪在 plan mode 補問的決定，這些決定沒有回到決策樹、也沒有回頭檢查既有的 D 項；1 項（R1#6）是兩個決定之間的交互作用沒有被追問；1 項（R1#8）是 agent 寫規格時自己推導的假設和 AC 衝突。另外 1 項 Factual Error（R1#1）是規格寫錯事實。單一分支內的問題問得很完整，但「新的決定改變了之前已經關閉的分支」時，沒有重新打開那個分支。官方文件也提到前沿有這個限制（frontier 是憑判斷選的，沒辦法自動算出來）。
