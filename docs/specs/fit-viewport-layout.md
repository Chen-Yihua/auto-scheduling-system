# 頁面依螢幕高度排版、任務列表分頁

- 狀態：已核准
- 等級：一般（只改前端畫面的排版與任務列表的顯示方式，不改資料、登入權限、外部系統同步，也不改 API）
- PR：#184

## 簡短說明

新增任務的視窗內容太長時按不到按鈕；首頁、分析頁在一般筆電上只能往下捲一點點。這份規格讓視窗內可以捲動，讓首頁、排程頁、分析頁在寬螢幕上依螢幕高度調整元件大小、放得下就不捲動，並讓任務管理頁的任務列表超過 30 筆時分頁。

## 背景

1. **新增任務的視窗按不到按鈕**：使用者在任務管理頁按「新增任務」，再按幾次「新增階段」後，視窗底部的「取消」「提交」被切掉，按不到。
   - 原因：Nuxt UI 3.1.0 的 UModal 外框已經限制最高高度：螢幕高度減 2rem，寬度 640px 以上減 4rem（`max-h-[calc(100dvh-2rem)] sm:max-h-[calc(100dvh-4rem)]`，見 `node_modules/@nuxt/ui/dist/shared/ui.D7lOOabO.mjs` 的 `modal` 主題）。但視窗裡的表單 `UForm`（[TaskEditModal.vue:102-107](../../frontend/components/tasks/TaskEditModal.vue)）沒有設定可以捲動，超出外框的部分直接被切掉。
   - 編輯任務用的是同一個視窗，從任務管理頁的「編輯」或首頁「今日」卡片的「修改」打開。編輯主任務時列出很多階段，也會發生同樣的問題。
2. **首頁只能往下捲一點點**：首頁的 Google 行事曆固定 600px 高（[GoogleCalendarEmbed.vue:37、51](../../frontend/components/dashboard/GoogleCalendarEmbed.vue)）。加上標題列（AppHeader）、Dashboard 的 `p-4`、`mt-4` 與卡片標題，總高度大約 830px，比一般筆電上瀏覽器的可視高度多一點，所以只能往下捲一點。
3. **分析頁只能往下捲一點點**：分析頁（[productivity.vue](../../frontend/pages/productivity.vue)）的元件都是固定大小，由上到下排成一欄：4 張數字卡片、「近 N 週完成數」長條圖（最高 256px，`max-h-64`，[WeeklyBarChart.vue](../../frontend/components/productivity/WeeklyBarChart.vue)）、「依來源」「依優先度」兩張並排的卡片。總高度在一般筆電上略高於可視高度。規格審查依 CSS class 估算（誤差約 ±20px）：
   - 一欄的排法：長條圖以外的元件合計約 690px，即使長條圖縮到 160px，在 768px 高的視窗仍然放不下。
   - 「依來源」「依優先度」上下疊在右欄：右欄約 430～560px，加上上方約 310px，仍然超過 781px。
   - 所以寬螢幕時改成「左側一直排數字卡片、右側上方長條圖、右側下方兩張卡片並排」（需求 13～16），估算見實作計畫第 3 節。
4. **排程頁第 2 步要捲到底才按得到按鈕**：第 2 步「確認截止日期與時長」每個任務一張卡片（約 90px 高），任務多時「確認並產生排程建議」按鈕在頁面最下面（[schedule.vue](../../frontend/pages/schedule.vue)）。
5. **排程頁第 3 步的確認按鈕在卡片內容裡**：「確認排程並寫入 Calendar」在「排程建議」卡片的內容區最上面（[ScheduleSuggestion.vue:73-85](../../frontend/components/tasks/ScheduleSuggestion.vue)），不在卡片標題列；卡片改成在裡面捲動後，往下看完清單要捲回上面才按得到。
6. **任務管理頁一次列出全部任務**：「任務列表」卡片（[TaskForm.vue](../../frontend/components/tasks/TaskForm.vue)）把所有主任務、一般任務與外部平台項目一次列出，每列約 50px 高。任務多時整頁一直往下捲。
   - 列表的順序來自後端：手動任務依資料庫順序（建立先後）排在前面，外部平台的項目接在後面（[schedulable_items.py:100-118](../../backend/crud/schedulable_items.py)）。

規格裡的「寬螢幕」指瀏覽器視窗寬度 1024px 以上，也就是首頁目前顯示三欄的寬度（Tailwind 的 `lg`）；「窄螢幕」指寬度小於 1024px。

## 需求

### 新增／編輯任務視窗

1. 視窗頂端的標題（「新增任務」或「編輯任務」）固定不動。
2. 視窗底部那一排按鈕（「刪除」「取消」「提交」或「儲存變更」）固定不動。
3. 標題與按鈕之間的內容超過視窗可用高度時，在視窗裡面捲動。
4. 新增與編輯共用同一個視窗，兩種情況都照 1～3。

### 首頁

5. 寬螢幕時，整頁高度等於瀏覽器視窗高度，不出現整頁的捲軸。
6. 寬螢幕時，Google 行事曆的高度填滿中間欄剩下的空間，不再固定 600px。
7. 寬螢幕時，Google 行事曆最少保留 400px 高。
8. 寬螢幕時，視窗矮到放不下 400px 的行事曆時，整頁才捲動。
9. 寬螢幕時，「今日」卡片的內容超過可用高度時，在卡片裡面捲動。
10. 寬螢幕時，右欄（Hacker News、LeetCode）的內容超過可用高度時，在右欄裡面捲動。按「顯示更多」「顯示範例」展開後也一樣。
11. 窄螢幕時，三張卡片疊成一欄，維持現在的整頁捲動。

### 分析頁

12. 寬螢幕時，整頁高度等於瀏覽器視窗高度，不出現整頁的捲軸。
13. 寬螢幕時，標題列（「工作效率」、統計時間、外部平台上次同步）下面分成左右兩區。
14. 寬螢幕時，左區由上到下一直排 4 張數字卡片（完成率、逾期、剩餘預估工時、準時完成率）。
15. 寬螢幕時，右區上方是「近 N 週完成數」長條圖卡片。
16. 寬螢幕時，右區下方是「依來源」「依優先度」兩張卡片，左右並排，高度跟著內容。
17. 寬螢幕時，長條圖依右區上方剩下的高度縮放。
18. 寬螢幕時，長條圖最少 160px 高。
19. 寬螢幕時，視窗矮到放不下時，整頁才捲動。
20. 窄螢幕時，維持現在的排列與整頁捲動。

### 排程頁

21. 寬螢幕時，整頁高度等於瀏覽器視窗高度，不出現整頁的捲軸。
22. 寬螢幕時，上方的步驟列（例如「1 拖拉排序優先權 → 2 確認截止日期與時長 → 3 查看排程建議」）固定不動。
23. 寬螢幕時，第 1 步、第 2 步、「處理已刪除的事件」底部的按鈕（「下一步」「取消」「上一步」「確認並產生排程建議」）固定在畫面下方，不用捲到底才按得到。
24. 寬螢幕時，第 1 步「拖拉排序優先權」的低、中、高三欄，內容超過可用高度時各自在欄位裡面捲動。
25. 第 1 步的任務仍然可以拖到任何欄位的任何位置，包括欄位裡捲動才看得到的位置。
26. 寬螢幕時，第 2 步「排程偏好設定」與任務卡片在同一個區塊裡捲動。
27. 寬螢幕時，第 3 步「排程建議」卡片的內容超過可用高度時，在卡片裡面捲動。
28. 第 3 步「排程建議」卡片的標題列（「排程建議」「重新產生」）固定不動。
29. 「確認排程並寫入 Calendar」按鈕從卡片內容區移到標題列，放在「重新產生」的右邊。寬窄螢幕都一樣。
30. 「確認排程並寫入 Calendar」的顯示條件不變：有「已排入時段」的任務時才顯示；載入中、Google Calendar 未連接、沒有可排程的任務時不顯示。
31. 窄螢幕時，第 3 步標題列放不下時，「重新產生」「確認排程並寫入 Calendar」換到「排程建議」下面一行，按鈕文字完整顯示。
32. 寬螢幕時，「處理已刪除的事件」的清單超過可用高度時，在清單區塊裡面捲動。
33. 窄螢幕時，排程頁維持現在的整頁捲動。

### 任務管理頁

34. 寬螢幕時，任務列表放得下就不出現整頁的捲軸（不會只能往下捲一點點）。
35. 任務列表超過可用高度時，整頁往下捲動，不在卡片裡面捲動。
36. 任務列表以每一列頂層的項目為單位分頁，每頁最多 30 筆。頂層的項目是主任務、一般任務與外部平台項目（GitHub、Jira、Moodle），每個算一筆。
37. 主任務展開的階段，跟主任務排在同一頁，不算進 30 筆。
38. 超過 30 筆時，才在列表的最下面顯示分頁按鈕；30 筆以內不顯示。
39. 換頁後，頁面捲到「任務列表」卡片的頂端。
40. 刪除任務、同步外部平台後筆數變少，目前這一頁已經不存在時，改顯示新的最後一頁。
41. 新增任務後，任務列表停在目前這一頁，不跳到新任務所在的頁。
42. 任務管理頁有「回到頂端」按鈕，固定在螢幕右下角，捲動時不跟著移動。
43. 「回到頂端」按鈕在往下捲超過一個瀏覽器視窗高度後才出現；捲回來不到一個視窗高度時隱藏，出現和隱藏用同一個門檻。
44. 按「回到頂端」後，頁面平滑捲回最上面。
45. 新增／編輯任務視窗打開時，「回到頂端」按鈕隱藏；視窗關閉後，再依捲動位置決定是否顯示。
46. 任務管理頁的新增任務視窗照需求 1～4。
47. 任務列表讀取中時（顯示載入中的骨架畫面），不顯示分頁按鈕。

## 不做

- GitHub、Jira、Moodle 三個平台頁面不改。
- 首頁「今日」卡片給外部平台項目用的「修改任務」小視窗（[TodayTasks.vue](../../frontend/components/dashboard/TodayTasks.vue) 的 `data-testid="external-form"`）不改：只有截止日期、所需時長兩個欄位，不會超出螢幕。
- 排程頁的清單不分頁。
- 任務管理頁以外的頁面不加「回到頂端」按鈕。
- 右下角的通知（例如「儲存成功」）出現時暫時蓋住「回到頂端」按鈕，不處理：幾秒後通知消失，不影響操作。
- 分析頁在 1366×768 這類較矮的筆電，同時顯示「外部平台上次同步」與「有 N 個任務……沒有列入每週趨勢」時，整頁可能多捲幾 px，不處理：很少遇到，只影響外觀、不影響功能。AC11 驗證時不顯示「沒有列入每週趨勢」那一行。
- 任務管理頁的分頁不記住頁碼：重新整理或離開再回來時，從第 1 頁開始。

## 假設

1. 首頁右欄的 Hacker News 與 LeetCode 兩張卡片疊在同一個可捲動的欄位裡，整欄一起捲動，不是兩張卡片各自捲動：兩張卡片的內容長度差很多（LeetCode 題目可能很長），各分一半高度會讓 Hacker News 卡片留下大片空白。
2. 首頁「今日」卡片的高度跟著內容，最高到左欄的高度，超過才在卡片裡面捲動；內容少時不拉長成整欄高：拉長只會留下空白。
3. 寬螢幕時，首頁、分析頁、排程頁的整頁高度一律用「瀏覽器視窗高度」計算（CSS 的 `dvh`），標題列（AppHeader）換行變高時，下面的內容自動變矮，不寫死標題列的高度。任務管理頁不限制整頁高度（需求 35），只調整外距讓少量任務時不多出捲動（需求 34）。
4. 分頁按鈕用 Nuxt UI 內建的 UPagination，不自己寫：專案已經在用 Nuxt UI 3.1.0。
5. 「回到頂端」按鈕用 UButton 加箭頭圖示（`i-lucide-arrow-up`），不另外裝套件。
6. 分析頁寬螢幕時，頁面內容最寬從 `max-w-4xl`（896px）加寬到 `max-w-6xl`（1152px），左區佔 1/4 寬、右區佔 3/4 寬（`lg:grid-cols-4`，右區 `lg:col-span-3`）：左區太窄時，數字卡片的說明文字會折行，4 張疊起來放不下。

## 驗證用的視窗大小

驗收條件裡的視窗大小，指瀏覽器裡網頁可用的寬×高（Console 輸入 `innerWidth + 'x' + innerHeight` 看得到的數字），用瀏覽器開發者工具的「裝置模擬」設定：

| 名稱 | 大小 | 代表 |
|---|---|---|
| 大螢幕 | 1920×1080 | 桌機螢幕 |
| 開發者的筆電 | 1182×781 | 開發者平常使用的筆電瀏覽器 |
| 一般筆電 | 1366×768 | 常見的筆電 |
| 矮螢幕 | 1024×500 | 寬螢幕裡最矮的情況，放不下最小高度 |
| 手機 | 390×844 | 窄螢幕 |

「三種寬螢幕」指大螢幕、開發者的筆電、一般筆電。「整頁沒有捲軸」指在頁面空白處滾動滑鼠滾輪，頁面不動。

## 不適用的情境

| 情境 | 原因 |
|---|---|
| 失敗、空資料、載入中 | 錯誤訊息、空資料說明與載入中的骨架畫面（USkeleton）的內容與出現條件不變；只是放進新的版面，內容比正常資料少，不會超出高度。任務列表沒有任務時，沒有分頁按鈕（AC26 的「30 筆以內不顯示」涵蓋）。第 3 步確認按鈕在載入中、未連接、空資料時不顯示，由 AC21 涵蓋 |
| 未登入 | 訪客看到的登入提示卡（LoginRequiredCard）內容不變，高度很小，放得下；任務管理頁訪客看不到列表，「回到頂端」不會出現（頁面不夠長） |
| 資料處理與一致性、同時操作 | 分頁只影響畫面上顯示哪些列，不改送給後端的請求；任務資料、排序與排程規則不變。「確認排程並寫入 Calendar」只改位置，按下後呼叫的 `confirmSchedule` 不變 |
| 安全性 | 沒有新的輸入欄位，也沒有新的 API |
| 和既有規則交會 | 排程頁第 1 步的階段拖拉限制（`stageMoveBlockReason`）不變，AC17 只驗證捲動後仍然拖得到；AC16、AC17 用沒有階段的任務，避免拖拉被階段限制擋下 |

## 實作計畫

### 共同做法

寬螢幕時的「整頁等於視窗高度」用 flex 欄排版：頁面最外層 `lg:h-dvh flex flex-col`，AppHeader 不縮（`shrink-0`），下面的內容區 `flex-1 lg:min-h-0`，要捲動的區塊加 `lg:overflow-y-auto`。這樣標題列換行變高時，內容區自動變矮（假設 3），不用寫死高度。窄螢幕時這些 `lg:` 開頭的設定都不生效，維持現在的整頁捲動。

最少高度（首頁行事曆 400px、分析頁圖表 160px）用 `lg:min-h-[…]`。視窗矮到放不下時，內容會超出 `h-dvh`，整頁出現捲軸（需求 8、19）；實作時要確認超出後，底部的內距沒有被切掉（例如把最外層改成 `lg:min-h-dvh` 搭配內容區 `lg:h-…`，或其他能讓 AC7、AC14 成立的寫法）。

UCard 要在卡片裡捲動時，用 `:ui` 讓 root 變成 flex 欄、body `flex-1 min-h-0 overflow-y-auto`（Nuxt UI 3.1.0 的 card 主題：root、header、body、footer 四個 slot）。
