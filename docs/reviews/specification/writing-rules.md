## 問題說明

### #1 替換用詞會改到 ADR 清單抄自 ADR 的標題

`docs/decisions/README.md:40-41` 的清單表抄了 ADR 0009、0010 的標題與狀態，裡面有「落點」「暫存產物」。照原本的驗收條件替換，清單上的標題會和 ADR 檔對不上，ADR 檔本身又不改。

### #36 寫法問題列成規格問題後，照現有規則會一律問開發者

`write-spec/SKILL.md:32` 把「規格內容互相矛盾或沒有依據」整類放在「問開發者」。所以寫法問題歸進這一類，每一項都會問開發者，和開發者要的分法（只有會改到產品行為的才問）不同。

### #43 只換說法的寫法問題和兩個 agent 的現有規則接不上

`feature-implementer.md` 規定不做沒有對應驗收條件的要求，`acceptance-reviewer.md` 寫不阻擋的發現會開成 issue。這兩條都和「只換說法的由寫的人在同一個 PR 改」衝突。

## 已接受的風險

- 永久保存的文件（`docs/specs/`、`docs/reviews/`、`docs/decisions/` 與 ADR 清單表）和 `docs/experiments/` 保留舊名稱與舊用詞，讀舊紀錄的人靠「流程用語」的對照表查。
