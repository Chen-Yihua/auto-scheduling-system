# 功能開發流程

需求：$ARGUMENTS

## 1. 需求與計畫（plan mode）

先進入 plan mode，自己讀程式碼，寫成一份計畫交給開發者核准：

- **需求**：要做什麼、不做什麼。
- **假設**：程式碼看不出來、由你自行判斷的業務規則，逐條列出。只有無法合理假設、而且會影響整體方向的問題才先問。
- **驗收條件**：「在 X 情況下，系統要 Y」，每條都要能驗證。
- **計畫**：要改的檔案、步驟、每條驗收條件對應的測試。

開發者要求修改時，更新整份計畫再交一次，直到核准。

## 2. 實作（核准後自動進行，不再中途詢問）

- 照 CLAUDE.md「開發流程」開分支；先寫測試並確認在改程式前會失敗，再實作。
- 只做計畫內的事。計畫有錯、需要改變範圍時，停下來回報。
- 跑「完成的定義」的檢查 → commit → push → 開 PR → 等 CI。CI 失敗就讀 log 修正，最多 3 輪，仍失敗就停下來回報。

## 3. 驗收

- 交給 `acceptance-reviewer` agent，附上核准的驗收條件和分支名稱；它指出的問題修正後再驗一次。
- 最後回報：PR 連結、驗收表（驗收條件 → 對應的測試 → 結果）、假設清單、範圍外發現的問題。PR 描述放同一張驗收表。
