# 0002. 功能規格放進 repo，和程式碼同一個 PR

- 狀態：已採用（文字修正不寫規格的例外見 [0007](0007-process-depth-by-risk.md)）
- 日期：2026-11-02

## 背景

`/feature` 原本把計畫寫在本機的 plan 檔（repo 以外）。驗收時新增或修改驗收條件，只有那份本機檔案知道；PR 看不出驗收條件改過什麼，也無法檢查「改了程式，驗收條件有沒有一起改」。實作和審查的 agent 也得依賴那份本機檔案。

## 決定

每個功能的規格放在 `docs/specs/<功能>.md`，和程式碼放在同一個 PR。驗收條件有編號（AC1、AC2…），新增或修改都記在規格的「修改紀錄」，測試與 PR 驗收表用同一套編號對應。

## 放棄的做法

- **只寫在 PR 描述**：PR 描述沒有版本紀錄，改過什麼看不出來，合併後也不容易找。
- **寫在 issue**：要跨系統查，agent 讀取也要多一步。

## 影響

- repo 多一個 `docs/specs/` 目錄，規格會隨功能累積。
- 審查時要確認每個新測試都對應到規格裡的驗收條件，驗收條件的修改也有出現在 PR 的 diff 裡。
