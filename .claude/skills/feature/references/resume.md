# 暫停、接續與暫存檔遺失

> 什麼時候讀：暫停或接續一次開發，或草稿資料夾（`.drafts/`）裡這次的暫存檔不見時。

## 暫停與接續

直接用草稿資料夾裡這次的暫存檔接著做，不用複製。

## 暫存檔遺失時

照遺失的是哪個暫存檔處理，不看遺失的時間點（時間點列舉不完）。做錯時，已核准的內容可能被憑記憶重寫，所以照順序做：

1. 先 `git fetch`，到下表「正式版本」找。找到就以它為準，不憑記憶重新產生；之後要修改時才複製回草稿資料夾。
2. 有部分成果時（例如分支上已改了一部分），逐項標出已完成、未完成、待確認；確認不了的標「待確認」，不推定已完成。
3. 告訴開發者你依據的來源（分支、commit、有沒有未 commit 的改動），請開發者確認有沒有漏掉的決定。沒有依據的項目要重新核准才執行。
4. 找不到正式版本時，問開發者要重做還是不補。已核准的內容重做後要重新核准。不補時，在 PR 描述記下遺失了什麼、有什麼影響。

## 暫存檔表

這是暫存檔唯一的清單。開始前的檢查、清理、取消都用這些確切的檔名比對；要新增暫存檔時，先加進這張表。

| 暫存檔 | 檔名 | 遺失時的正式版本 |
|---|---|---|
| 已確認的決定與待問 | `<功能>-grill.md` | 核准後以規格為準；核准前從需求問答重做 |
| 術語 | `<功能>-glossary.md` | PR 分支或 `origin/main` 的 `docs/glossary.md`；核准前重新確認 |
| 規格草稿（文字修正是改動清單） | `<功能>-spec.md` | PR 分支的 `docs/specs/<功能>.md`；快速路徑是 PR 描述（`gh api repos/{owner}/{repo}/pulls/<PR> --jq .body`）。都找不到時，問開發者要重寫再核准還是取消 |
| ADR 草稿 | `<功能>-adr-<名稱>.md` | PR 分支的 `docs/decisions/`；沒有時重寫，和規格一起重新核准 |
| 審查報告 | `<功能>-spec-review-r<N>.md`、`<功能>-impl-review-r<N>.md`（N 是第幾輪） | 已貼出的看 PR 留言（`gh pr view <PR> --json comments`）；還沒貼出的問開發者要重跑還是不補 |
| 改寫過漏洞細節的留言 | `<功能>-spec-review-r<N>-comment.md`、`<功能>-impl-review-r<N>-comment.md` | PR 留言，不重建 |
| 上一版規格 | `<功能>-spec-v<N>.md` | 只給第 2 次規格審查比對用，不恢復 |
| advisory 內容 | `<功能>-advisory.json` | GitHub 上的 advisory（用 GHSA 編號讀回） |
| PR 描述 | `<功能>-pr-body.md` | GitHub 上的 PR 描述 |
