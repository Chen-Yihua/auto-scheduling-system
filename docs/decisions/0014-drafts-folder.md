# 0014. 核准前的草稿放在 repo 內被 git 排除的 `.drafts/`

- 狀態：已採用
- 日期：2026-11-20

## 背景

[0008](0008-grilling-without-plan-mode.md) 決定 `/feature`、`/issue` 核准前只寫 scratchpad：規格草稿、問答紀錄、ADR 草稿、審查報告原文都放在 session 專用的暫存資料夾（`/tmp/claude-0/<專案>/<session id>/scratchpad/`）。這個 repo 是單人開發，核准前只維護一份工作草稿，核准後才轉成正式文件 commit。

實際使用時有兩個問題：

- 開發者要看草稿時，要自己到 `/tmp` 底下依 session id 找資料夾，VS Code 的檔案列表看不到。
- session 結束、重開機或系統清理後，scratchpad 可能不見。[0010](0010-scratchpad-loss-recovery.md) 為此設計了遺失後的恢復步驟；暫停後接續時，[0009](0009-docs-delivery-and-glossary.md) 要求把檔案複製到新的 scratchpad（`resume.md` 另外要開發者提供舊路徑）。

[0010](0010-scratchpad-loss-recovery.md) 當時放棄「把 scratchpad 改到 repo 內的資料夾」，理由是「核准前不改 repo、不開分支」是既有的規則，並引用 [0009](0009-docs-delivery-and-glossary.md) 放棄「術語核准前直接寫進工作目錄」的理由：工作目錄是開發者與其他 session 共用的，未核准的內容可能被別的 commit 帶走；取消時也要還原。

## 決定

- 核准前的草稿與開發中的暫存檔，放在 repo 根目錄的 `.drafts/`（流程用語「草稿資料夾」），`.drafts/` 寫進 `.gitignore`。
- 資料夾裡不分子資料夾，檔名照舊用 `<功能>-` 開頭；暫存檔的種類以 `.claude/skills/feature/references/resume.md` 的暫存檔表為準，建立 security advisory 用的 JSON 也放這裡。
- 暫停與接續時，直接用 `.drafts/` 裡這次的檔案，不用提供舊路徑，也不用複製。
- 暫存檔表的每一種暫存檔都有確切的檔名，各輪審查報告原文是 `<功能>-spec-review-r<N>.md`、`<功能>-impl-review-r<N>.md`，第 2 次規格審查比對用的上一版規格是 `<功能>-spec-v<N>.md`。只建立表上的暫存檔；其他筆記直接寫進規格。
- 回報時，照 `/feature`「清理暫存」確認內容都已經寫進正式文件，再刪掉這次的暫存檔；取消時，術語怎麼處理決定好之後刪。只刪暫存檔表列出的確切檔名，不用「`<功能>-` 開頭」比對，避免刪到名稱開頭相同的其他功能（例如 `sync` 與 `sync-calendar`）。
- 開始 `/feature`、`/issue` 時，草稿資料夾裡已經有這次的暫存檔（例如上次中斷、漏刪，或 PR 被關閉後留下的），先問開發者要接續還是刪掉重來，不把舊檔的內容當成這次的決定。
- 暫存檔還是可能遺失（例如被刪除、換了一台機器），0010 以暫存檔為單位的恢復步驟與審查規則保留，對象從「scratchpad 遺失」改成「草稿資料夾裡這次的暫存檔遺失」。
- 舊 scratchpad 裡的草稿不搬進 `.drafts/`。

「核准前不改 repo」這條規則由本 ADR 改成「核准前只寫草稿資料夾，不改 repo 裡其他檔案」。0009、0010 擔心的兩件事，現在這樣處理：

1. 被別的 commit 帶走：`.drafts/` 被 git 排除，`git add <路徑>` 會拒絕加入，`git add .`、`git add -A` 也不會帶到；只有刻意加 `-f` 才加得進去。
2. 取消時要還原：草稿不在被追蹤的檔案裡，取消時照暫存檔表的確切檔名刪掉這次的暫存檔就好，不用還原 repo。

## 放棄的做法

- **留在 scratchpad，每次交給開發者時附上連結**：解決找檔案的麻煩，但 scratchpad 仍會遺失，接續時仍要複製。
- **核准前就開分支和 PR，ADR 先寫「提議中」**（一般 ADR 的做法）：未核准的內容會進 git 歷史；核准發生在開分支之前，這個 repo 用不到「提議中」。
- **把舊 scratchpad 的草稿搬進 `.drafts/`**：已合併的工作有正式版本，未完成的工作很少，不值得逐一分類搬移。

## 影響

- `.drafts/` 在 VS Code 看得到、重開機還在；檔案不會自己消失，要靠回報與取消時刪除，漏刪會留在資料夾裡。
- 同一台機器上的其他 session 也看得到 `.drafts/` 的檔案；用暫存檔表的確切檔名區分。
- 審查報告原文與 advisory 的 JSON 可能寫了漏洞細節，它們只放在被 git 排除的 `.drafts/`；漏洞細節不寫進正式文件的規則照舊（`CLAUDE.md`「漏洞」）。
- 0008 的「核准前只寫 scratchpad」由本 ADR 取代，改成「核准前只寫草稿資料夾，不改 repo 裡其他檔案、不開分支」；0008 的其他決定照舊。
- 0009 的「接續時把暫存檔複製到新的 scratchpad」由本 ADR 取代；0009 的其他決定照舊。
- 0010 的遺失對象（scratchpad）由本 ADR 取代；以暫存檔為單位恢復、審查不逐一要求特定案例照舊。
