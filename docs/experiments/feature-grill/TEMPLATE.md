## 指標

| 指標 | 數值 | 怎麼算 |
|---|---|---|
| 需求釐清輪數 | | `/feature-grill`：第 0 節問了幾輪（含第 1 節補問）與總題數，寫成「N 輪 / M 題」。`/feature`：寫規格前問了幾次問題 |
| 人工介入次數 | | 預定的確認點以外，開發者必須出手的次數：回答 Missing AC、糾正 agent 方向、補充漏掉的資訊、中斷流程。回答問答輪、核准規格、決定合併不算 |
| Missing AC | Critical N / Major N / Minor N | 規格核准後才發現的缺漏，明細列在下面 |
| Review 輪數 | | `docs/reviews/<功能>-round<N>.md` 的份數 |
| 假設被否決數量 | | 規格「假設」交給開發者核准時，被否決或改寫的條數 / 假設總條數 |
| 需求變更次數 | | 規格核准後，「修改紀錄」的筆數 |
| Token | 釐清後：… / 結束時：… | 開發者在問答確認後與流程結束時各執行一次 `/cost` 的數字；`/feature` 只有結束時 |
| 開發時間 | 釐清：… / 規格：… / 實作與審查：… / 總計：… | 由各階段結束時記下的時間計算；等開發者回覆的時間包含在內 |
