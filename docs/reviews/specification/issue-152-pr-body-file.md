## 問題說明

### #1 開 4 個後續 issue 只寫在實作計畫，沒有需求與驗收條件

PR 帶 `Closes #152`，合併後 #152 會自動關閉。這 4 個 issue 如果沒開，已核准的方向就不會留在任何追蹤的地方，而 `acceptance-reviewer` 只照驗收條件審查。依據：規格「實作計畫」第 4 步，對照「需求」1–3、AC1–AC3。

### #2 實作計畫第 4 步的方向細節在問答紀錄的「已確認」找不到

reviewer 擔心開發者沒決定過的規則，會以「已核准」的名義寫進 issue。查證後確認，這些細節都在第 1 輪問答 Q4～Q7 的建議答案裡，開發者回答「Q4～Q7 照建議」。
