# 功能開發流程

需求：$ARGUMENTS

## 1. 需求分析（不改任何檔案）

- 讀相關程式碼，列出要改什麼、不改什麼、會影響哪些檔案（前後端連動見 CLAUDE.md）。
- 寫出驗收條件，每條都要能驗證：「在 X 情況下，系統要 Y」。
- 業務規則不確定就問，不要自己假設。
- 停下來等開發者確認驗收條件，確認前不改檔案。

## 2. 測試

- 每條驗收條件至少對應一個測試，範圍照 CLAUDE.md「測試範圍」。
- 能先寫的測試先寫，並確認在改程式前會失敗，證明它真的測到新行為。

## 3. 實作

- 照 CLAUDE.md「開發流程」開分支。
- 只做驗收條件範圍內的事；發現範圍外的問題，最後再回報，不要順手改。

## 4. 驗收

- 跑「完成的定義」的檢查，開 PR，等 CI 通過。
- 回報驗收表：驗收條件 → 對應的測試 → 結果。沒有測試涵蓋的條件，要說明是怎麼驗證的。PR 描述也放同一張表。
