## 問題說明

### #1 提示的標題寫法和需求問答確認的不一致

需求問答的文字寫「提示標題用『因後面階段比前面優先序高…』」，但開發者看過的範例是標題「已建立主任務和 N 個階段」、下一行才是這句。草稿照範例寫，沒有標成要開發者決定。

### #2 新增單一階段沒有被調整時，沒有 AC 保證清單是空的

新增階段的回應以主任務文件為底（`backend/routers/manual_task.py:214-215`、`:224-229`），主任務文件上存的清單會自然出現在回應裡。實作只在「這次有調整」時覆蓋，提示就會說明一筆沒發生的調整。

### #3 需求 1、4、AC2 對調整規則的描述和程式不完全相符

staged-tasks AC6 寫「比後一個階段低時調成和後一個階段一樣」，程式比對的是後面不在這次推斷範圍內的階段中的最高值（`backend/crud/manual_task.py:117-124`）；新增單一階段時只有新階段算推斷的（`backend/routers/manual_task.py:202`）。

### #4 兩次請求之間階段被刪除或改名時，提示怎麼顯示沒有定義

清單只存子任務 id，標題在顯示時從回應的 `subtasks` 查；被刪掉的階段會查不到，可能顯示空的標題。

## 已接受的風險

- 同一個 key 先新增階段、再建立任務時，建立任務回傳那個階段的資料和它的清單：原本就有的行為，另開 #118。
- 提示用的是目前的標題，可能和第一次建立時不同；被調整或被比較的階段在重送前被刪掉時，那一行不顯示：開發者決定。
- 重送前插入新階段時，「前一個階段」指的是調整當時的前一個階段：開發者決定接受。
- 提示的分行不寫自動化測試，由實作在開 PR 前確認畫面並寫在 PR 描述。
